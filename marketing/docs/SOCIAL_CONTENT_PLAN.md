# Petty X and Reddit Social Content Plan

## Scope

This plan covers launch content for X and Reddit using real Petty app footage,
screenshots, and existing 2D character assets.

It is a planning document, not final post copy.

## Product Truth

All posts must stay within current app behavior:

- Native macOS menu bar app.
- Transparent, borderless desktop character window.
- Nine bundled 2D characters in the Character Store.
- Immediate character selection.
- Draggable desktop placement.
- Size control from 75% to 135%.
- Click/poke animation.
- Activity response to pointer movement and typing.
- Bored/sleep state after real system idle time.
- Always On Top, Show, Hide, and Reset Position controls.

Do not imply:

- Paid character packs, purchases, unlocks, rarity, or a marketplace.
- Accounts, cloud sync, AI chat, or generated behavior.
- User counts, revenue, downloads, testimonials, or traction not supported by
  evidence.
- Skeletal animation, physics, or reactions not visible in the current app.

## Positioning

### One-sentence description

Petty is a native macOS desktop companion that lets you choose a 2D character,
move and resize it, and watch it react while you work.

### Core value

Petty makes a quiet Mac desktop feel more personal without becoming another
large productivity app.

### Collectible framing

Use "collectible" to describe the pleasure of browsing and switching between a
library of distinct characters.

Do not use collectible language to imply:

- Scarcity.
- Ownership tokens.
- Purchases.
- Unlock progression.
- Limited editions.
- Trading.

### Tone

- Builder-led.
- Direct.
- Curious.
- Specific about implementation and current behavior.
- Lightly playful without sounding like a toy advertisement.
- Honest about prototype status where relevant.

Avoid:

- "Revolutionary," "game-changing," or "the future of productivity."
- Corporate launch language.
- Fake urgency.
- Engagement bait.
- Claims that everyone needs a desktop pet.

## Content Pillars

1. **Product proof**

   Show Petty running on a real Mac desktop.

2. **Interaction**

   Demonstrate choose, drag, resize, click, activity, and sleep behavior.

3. **Character library**

   Show distinct real 2D assets and ask people which one they would use.

4. **Build story**

   Explain the native macOS and authored-PNG implementation without turning
   every post into a technical thread.

5. **Feedback loop**

   Ask focused questions that can guide the next product decision.

## Asset Rules

- Use real app recordings for behavior claims.
- Use real transparent PNG assets for character-focused images.
- Use 2D backgrounds and layouts that fit the source art.
- Keep app screenshots unchanged except for cropping and private-data masking.
- Include attribution where required by the source asset license or publishing
  context.
- Prefer a short MP4 over a GIF when the platform supports autoplay video.
- Never generate replacement characters or fake UI.

## X Content Plan

## X Post 1 - Launch Product Proof

**Post angle**

Introduce Petty with the complete interaction loop rather than a long
explanation.

**Asset needed**

30-second landscape launch video based on real app footage.

**Caption idea**

> I built Petty, a tiny native macOS companion that lives on your desktop.
>
> Choose a 2D character, drag it anywhere, resize it, click it, and watch it
> react while you work.
>
> Still early, but the core loop is working.

Open Petty, browse the Character Store, select Graveyard Intern, drag and
resize it, trigger a poke reaction, show active behavior, then switch between
three characters.

**CTA**

> Which character would you keep on your desktop?

**Why this should go first**

It proves the product exists and explains the core loop in one post.

## X Post 2 - Choose Your Companion

## X Post 3 - Drag-Speed Response

**Post angle**

Show that dragging is an interaction, not only window movement.

**Caption idea**

**Visual concept**

Split the clip into two labeled moments: `SLOW DRAG` and `FAST DRAG`. Keep the
same character, starting position, and desktop.

**CTA**

**Visual concept**

## X Post 5 - It Reacts While You Work

Cursor approaches, clicks once, and the full 1.2-second reaction plays. Avoid

**CTA**

**CTA**

The poll itself.

## Reddit Content Plan

## Reddit Post 1 - Native macOS App Show-and-Tell

**Target subreddit type**

Mac apps, macOS software, indie app showcases, and communities that permit
developer self-posts.

**Post angle**

Show the working app and ask for feedback on whether the interaction feels
appropriately native and unobtrusive.

**Asset needed**

30-second real-footage launch trailer, plus one clean desktop screenshot if the
subreddit supports galleries.

**Title idea**

> I built a native macOS desktop companion with draggable 2D characters

**Body outline**

1. One sentence describing Petty.
2. State that it is a native macOS menu bar app.
3. List current interactions: choose, drag, resize, click, activity response,
   and idle/rest.
4. Mention nine bundled 2D characters.
5. Explain that the video is current real app footage.
6. Ask one focused question: does it feel fun or distracting at desktop scale?
7. Link the repository only if subreddit rules allow it.

**What to avoid**

- Do not use "please support/upvote."
- Do not lead with a download link.
- Do not paste a feature-marketing wall of text.
- Do not imply App Store availability if it is not packaged there.
- Do not cross-post the exact same title/body without adapting to community
  rules.

**Why this should go first**

It reaches people who understand Mac-native behavior and can evaluate the core
experience rather than only the character art.

## Reddit Post 2 - Indie Developer Build Breakdown

**Target subreddit type**

Indie development, side projects, programming projects, and build-in-public
communities.

**Post angle**

Explain the technical decisions behind a transparent desktop character.

**Asset needed**

Short drag/resize video, menu bar screenshot, and optional simplified
architecture diagram.

**Title idea**

> What I learned building a transparent draggable desktop character for macOS

**Body outline**

1. Brief motivation for building Petty.
2. Explain the transparent borderless `NSPanel`.
3. Explain why panel size must grow with character scale.
4. Explain state mapping: idle, active, poke, drag, rest.
5. Mention system idle and pointer/keyboard timing without inspecting typed
   content.
6. Share one unresolved design question.
7. Invite technical critique.

**What to avoid**

- Do not turn it into a hidden product advertisement.
- Do not overstate technical novelty.
- Do not omit implementation tradeoffs.
- Do not include private logs or machine-specific paths.
- Do not claim Rive is the active renderer; current characters use PNG frames.

## Reddit Post 3 - 2D Animation and Game Asset Discussion

**Target subreddit type**

2D game art, animation, sprite, open-game-asset, and game-development
communities that permit tool/project discussion.

**Post angle**

Ask how to improve desktop-scale readability and behavioral state mapping while
preserving the original authored art.

**Asset needed**

Four-state card for one character using real Idle, Walk, Attack, and Sleep/Dead
frames, plus a short desktop-size clip.

**Title idea**

> Mapping existing 2D character animations into a desktop companion: what reads
> best at small scale?

**Body outline**

1. Explain that Petty uses existing licensed 2D animation packs.
2. Show the four runtime slots.
3. Explain actual desktop rendering size.
4. Describe how walk maps to active/drag behavior and attack maps to click.
5. Ask whether state selection reads clearly at small scale.
6. Include source and license attribution.

**What to avoid**

- Do not ask the community to design free assets.
- Do not hide asset sources.
- Do not present sourced art as original art.
- Do not use AI-generated replacement characters.
- Do not frame recognizable third-party characters as Petty-owned IP.

## Reddit Post 4 - Productivity and Workspace Feedback

**Target subreddit type**

Digital workspace, desk setup, productivity-tool, and focus-app communities
that allow experimental app discussion.

**Post angle**

Ask whether a reactive desktop companion can add personality without becoming a
distraction.

**Asset needed**

Real footage showing idle, typing response, and rest state on a clean desktop.

**Title idea**

> Would a small reactive desktop companion help your workspace feel better, or
> just distract you?

**Body outline**

1. Describe the experiment, not a productivity claim.
2. Explain that Petty reacts to recent pointer/keyboard activity.
3. Clarify that it does not inspect typed text or app content.
4. Show the real idle/rest behavior.
5. Ask about preferred visibility controls or focus modes.
6. Invite negative feedback as well as positive feedback.

**What to avoid**

- Do not claim productivity gains.
- Do not claim wellness, focus, or mental-health benefits.
- Do not use engagement bait.
- Do not hide privacy behavior.
- Do not post if the community prohibits self-promotion or app feedback.

## Reddit Post 5 - Character Choice Discussion

**Target subreddit type**

Casual software, desktop customization, pixel-art-adjacent, and community
show-and-tell spaces where character discussion is relevant and allowed.

**Post angle**

Let the character library start a low-pressure design conversation.

**Asset needed**

2D lineup image using all nine real character assets and a short selection
montage.

**Title idea**

> Which of these nine 2D characters would you keep on your Mac desktop?

**Body outline**

1. Explain that the image shows the current bundled character library.
2. List names in the same order as the visual.
3. State that selection is immediate inside the app.
4. Mention that each has idle, active, click, and rest animation slots.
5. Include attribution/source notes where needed.
6. Ask which visual style reads best at desktop scale and why.

**What to avoid**

- Do not describe characters as exclusive or collectible purchases.
- Do not run a popularity contest across many communities at once.
- Do not omit licensing context.
- Do not imply all character IP belongs to Petty.
- Do not use a generated lineup that changes the source art.

## Recommended Launch Order

The plan assumes the required real footage and image assets have been produced.

### Phase 1 - Establish product proof

**Day 1**

1. Publish X Post 1: Launch Product Proof.
2. Publish Reddit Post 1 in one carefully selected Mac-app or indie-app
   community, following its rules.

Do not publish to multiple Reddit communities on the same day with identical
copy.

### Phase 2 - Explain interaction

**Day 2 or 3**

3. Publish X Post 3: Drag-Speed Response.
4. Reply to launch-post questions with real clips rather than creating a second
   broad launch claim.

**Day 4**

5. Publish X Post 4: Resize Without Clipping.

### Phase 3 - Show personality and behavior

**Day 5 or 6**

6. Publish X Post 2: Choose Your Companion.
7. Publish X Post 6: Click/Poke Reactions later the same week, not the same
   day.

**Day 7 or later**

8. Publish Reddit Post 5 only in a community where character-choice discussion
   fits naturally.

### Phase 4 - Share the build

**Week 2**

9. Publish X Post 7: Native macOS Build Detail.
10. Publish Reddit Post 2: Indie Developer Build Breakdown.
11. Publish X Post 8: Authored 2D Animation States.
12. Publish Reddit Post 3 if its asset and licensing context are complete.

### Phase 5 - Ask for direction

**After meaningful replies have arrived**

13. Publish X Post 5: It Reacts While You Work.
14. Publish Reddit Post 4 for focused workspace/focus feedback.
15. Publish X Post 10: Focused Feedback Poll.
16. Use X Post 9 as a later build recap rather than another launch post.

## Reddit Posting Checklist

Before posting:

- [ ] Read the current subreddit rules.
- [ ] Confirm self-promotion or project feedback is allowed.
- [ ] Use a title that describes the project rather than advertising it.
- [ ] State clearly that you built the app.
- [ ] Use native media upload when appropriate.
- [ ] Adapt the body to the community instead of copying it verbatim.
- [ ] Include only one main link.
- [ ] Include attribution when character art is central to the post.
- [ ] Ask one focused question.
- [ ] Stay available to answer technical or product questions.

After posting:

- [ ] Reply directly and do not argue with negative feedback.
- [ ] Do not ask friends or other communities to manipulate votes.
- [ ] Do not repost quickly after poor performance.
- [ ] Record useful objections and feature questions.
- [ ] Correct any inaccurate product assumption in the comments.

## X Posting Checklist

- [ ] Put the product or character in the first frame.
- [ ] Keep the first sentence understandable without clicking "show more."
- [ ] Use one primary asset per post.
- [ ] Keep captions factual and conversational.
- [ ] Avoid more than one broad CTA.
- [ ] Add alt text to images.
- [ ] Check video captions and mobile readability.
- [ ] Do not tag unrelated accounts for reach.
- [ ] Use threads only when each reply adds evidence or useful build detail.

## Measurement Without Fake Traction

Track signals to guide the next post, not to manufacture a success narrative:

- Questions about installation or availability.
- Character preferences.
- Requests for specific behavior.
- Confusion about what the app does.
- Completion and replay behavior where platform analytics provide it.
- Meaningful repository visits after technical posts.
- Constructive comments from Mac users and developers.

Do not publish uncontextualized vanity metrics or imply demand from a small
number of reactions.

## Final Content Audit

Reject or revise a planned post if it:

- Uses generated or fake product footage.
- Replaces real character assets.
- Claims traction without evidence.
- Claims purchases, unlocks, rarity, or a marketplace.
- Claims productivity, wellness, or focus benefits without evidence.
- Hides the fact that the poster built the app.
- Omits required asset attribution.
- Uses identical Reddit copy across multiple communities.
- Asks for votes, support, or engagement rather than focused feedback.
- Describes a feature that cannot be shown in the current app.
